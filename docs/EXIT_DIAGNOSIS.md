# v0.8 · 虚拟X11退出异常的定位

此前v0.7首次启动独立运行包的探针偶发超过15秒未退出，而同一程序复测正常。本轮通过退出步骤与窗口属性定位到验收环境初始化，验收期限仍保持15秒。

## 原因与证据

没有窗口管理器的全新Xorg尚未注册WM_DELETE_WINDOW原子。Godot4.6.3的X11后端启动时使用`XInternAtom(..., "WM_DELETE_WINDOW", true)`，只查询已经存在的原子；因此冷启动可缓存None。探针直到关窗时才创建该原子，发出的正常关窗消息与引擎启动时缓存的值不一致，关闭回调不会触发。下一次启动时原子已经存在，所以复测正常。

依据是[Godot官方4.6.3-stable的X11实现](https://github.com/godotengine/godot/blob/4.6.3-stable/platform/linuxbsd/x11/display_server_x11.cpp)：启动的原子查询、ClientMessage比较与窗口协议设置。诊断副本保存在构建产物m08-godot-x11-source.cpp。

在仍未响应正常关闭消息的冷启动测试进程中，仅用于诊断的None原子消息触发了完整退出步骤：收到关闭请求、保存完成、音频停止、混音器等待完成、场景离开。这确认了启动时缓存值问题；正式验收始终发送正常WM_DELETE_WINDOW协议。

## 修正与重复验证

Linux验收工具现在在启动游戏之前注册正常窗口协议，承担空白虚拟显示中缺少的窗口管理器初始化；游戏核心仍执行正常保存与退出流程。退出期限仍是15秒。

窗口搜索还会短暂抓取一致的窗口树，并核对目标进程PID，避免启动／销毁时查询过期的临时窗口产生BadWindow。该问题属于探针窗口枚举竞争，也没有按游戏通过处理失败日志。

tools/cold_exit_check.py在独立Xorg上重复三轮，每轮先确认WM_DELETE_WINDOW不存在，再启动真实导出程序，完成系统键盘搜刮、返程、正常关窗和重启。结果保留初始缺失值、逐轮日志及实际程序SHA-256。持续运行验收另检查真实窗口关闭与原运行包恢复。

这是Linux虚拟显示的定位与修正，不能由此推断未实测Windows设备的退出行为。Windows验收使用系统原生CloseMainWindow／WM_CLOSE，并保留实际日志。
